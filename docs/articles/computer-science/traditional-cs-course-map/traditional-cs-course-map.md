学习 Python、享受程序给出正确结果，是接触计算机专业的一种入口。但传统计算机课程
并不只教人使用某种语言开发应用，它更关心一连串原理问题：信息怎样表示，指令怎样
执行，硬件怎样协作，系统怎样管理资源，程序又怎样变成机器可以运行的形式。

<!-- more -->

## 一条从 0 和 1 向上的路径

可以把经典课程粗略地放在一条抽象层次上：

```text
数字逻辑 -> 计算机组成与体系结构 -> 操作系统 -> 编译系统
        -> 数据结构与算法 -> 编程语言与应用
                         \-> 计算机网络
```

这不是严格的先修关系。真实系统会跨越多层，课程之间也会反复引用同一概念。这个视角
的用途，是先看清每门课主要回答什么问题。

## 数字逻辑：怎样用电路表达计算

数字系统把连续的物理世界抽象成离散状态，通常用 0 和 1 表示。课程会从布尔代数、
逻辑门和组合逻辑开始，再进入触发器、状态机和时序电路。加法器就是一个典型问题：
给定两组二进制输入，怎样组织逻辑门得到和与进位。

使用 Verilog、SystemVerilog 或 VHDL 时，代码描述的是硬件结构与行为，而不是给通用
处理器顺序执行的软件。综合工具会把描述转换为逻辑网络；后续还要经过布局、布线、
时序收敛和制造等环节。把 HDL 直接理解成“画出芯片版图”会漏掉中间很多步骤。

## 组成原理与体系结构：指令怎样跑起来

计算机组成原理通常围绕指令执行展开：取指、译码、执行、访存和写回。由此会遇到：

- 整数、浮点数和字符怎样编码；
- 算术逻辑单元怎样完成运算；
- 寄存器、缓存和主存怎样构成存储层次；
- 流水线、分支预测和并行性怎样影响性能；
- 输入输出设备怎样与处理器交换数据。

指令集架构是软件与硬件之间的重要接口。x86、Arm 和 RISC-V 定义了不同的指令、
寄存器与可见行为；微体系结构则决定某个具体处理器怎样实现这些约定。课程实验可能
让学生设计一个简化处理器，这时此前分散的数字逻辑会真正连成一台机器。

## 操作系统：怎样管理共享的机器

操作系统不只是图形界面。它在应用与硬件之间提供抽象，同时管理处理器时间、内存、
存储和设备。经典主题包括：

- 进程、线程、调度与同步；
- 虚拟内存和地址空间；
- 文件系统、缓存与持久化；
- 系统调用、权限与隔离；
- 中断、驱动和设备输入输出。

同时运行多个程序时，操作系统要决定谁获得 CPU、每个进程能访问哪些内存，以及故障
是否会影响其他程序。学习重点是这些机制与取舍，而不是记住某个桌面系统的操作方式。

## 编译系统：程序怎样变成可执行形式

编译器把源语言逐步转换为更低层的表示，常见阶段包括词法分析、语法分析、语义分析、
中间表示、优化和代码生成。链接器再把多个目标文件与库组织为可执行文件。

“编译型语言”和“解释型语言”只是方便交流的简化说法。以常见的 CPython 为例，Python
源码通常先编译为字节码，再由虚拟机执行；其他实现还可能使用即时编译。课程真正关注
的是语言规则如何被分析和实现，而不是给语言贴一个固定标签。

## 数据结构与算法：怎样组织数据和解决问题

数组、链表、栈、队列、树、图和散列表提供不同的数据组织方式。算法课程研究排序、
查找、图算法、动态规划等解决问题的方法，并用时间与空间复杂度比较它们。

这一层容易获得即时反馈：一道题可以运行、测试并衡量结果。但课程目标不只是刷题，
还包括为问题选择合适的模型，证明算法为何正确，并理解输入规模扩大后的成本。

## 编程语言与网络：表达计算，连接机器

学习 C、C++、Java 或 Python，一方面是在掌握语法与工具，另一方面也会接触类型系统、
作用域、内存模型、异常和并发等语言设计概念。编程语言让人用更高层的方式表达意图，
再由编译器、解释器和运行时落实到机器。

计算机网络则研究数据怎样跨设备传输。从链路、寻址和路由，到可靠传输、拥塞控制和
应用协议，各层都在用约定隐藏下一层细节。它既有信号与帧这样的底层内容，也会进入
HTTP、DNS 等直接面对应用的协议。

## 课程地图之外

数据库、人工智能、图形学、高性能计算、嵌入式系统、云计算、安全和人机交互等方向，
都建立在部分经典课程之上，又形成自己的理论与工程体系。计算机专业范围很广，不存在
一条覆盖所有方向的单一路线。

判断自己是否适合时，不必要求入门前已经懂这些原理。更有区分度的问题是：是否愿意
持续拆解抽象概念，是否能接受长时间调试和不确定性，以及是否对机器为何这样运行保持
好奇。会写出一个 Python 程序不是终点，但完全可以是一个可靠的起点。
